# ملخص نظام تحليلات العمل عن بُعد

## 1. فكرة النظام

النظام منصة لمتابعة إنتاجية الموظفين الذين يعملون عن بُعد. يتكون من ثلاثة تطبيقات مستقلة تتواصل فقط عبر REST API مؤمّن:

```text
وكيل الموظف على Windows ── HTTPS/REST ──> Backend API <── HTTPS/REST ── تطبيق المدير على الويب
                                              │
                                              ├── MySQL: البيانات المنظمة
                                              └── Screenshot Storage: ملفات اللقطات
```

- المدير يستخدم تطبيق الويب فقط.
- الموظف يستخدم وكيل Windows الخفيف فقط.
- تطبيق الويب ووكيل Windows لا يصلان إلى قاعدة البيانات مباشرة.
- الخادم مسؤول عن المصادقة والصلاحيات ومنطق العمل والتحليلات والتقارير والتخزين والإشعارات وسجلات التدقيق.

## 2. ماذا يفعل النظام حاليًا؟

### واجهة المدير

- تسجيل دخول آمن للمدير.
- إنشاء الموظفين وتفعيلهم أو إيقافهم.
- فتح ملف مستقل لكل موظف.
- إنشاء المهام وتحديد الموظف والأولوية والموعد النهائي.
- متابعة حالة المهمة ونسبة تقدمها.
- عرض لوحة إحصائية للإنتاجية والتركيز والوقت النشط والخمول.
- ترتيب الموظفين وفق الأداء.
- عرض استخدام التطبيقات وعناوين صفحات المتصفح.
- عرض لقطات الشاشة وربطها بالموظف ووقت الالتقاط.
- تشغيل التحليل الذكي وعرض الاتجاهات والتوصيات.
- تصدير التقارير بصيغ PDF وExcel وCSV.
- دعم العربية والإنجليزية واتجاهي RTL وLTR.
- دعم الوضع الفاتح والداكن مع حفظ اختيار المستخدم.

### وكيل الموظف على Windows

يعمل الجمع فقط عندما تكون جلسة العمل في حالة `ACTIVE`. عند الإيقاف المؤقت أو إنهاء الجلسة يتوقف الجمع.

يجمع الوكيل:

- التطبيق النشط واسم العملية.
- عنوان النافذة النشطة.
- قائمة التطبيقات المفتوحة.
- عنوان صفحة المتصفح في Chrome وEdge وFirefox وBrave عندما يكون متاحًا.
- مستوى نشاط لوحة المفاتيح دون تخزين أسماء المفاتيح أو النص المكتوب.
- مستوى حركة مؤشر الماوس دون تخزين إحداثيات المؤشر أو محتوى النقرات.
- وقت الخمول اعتمادًا على آخر إدخال مسجل في Windows.
- عدد مرات تبديل النافذة النشطة.
- عينة نشاط كل 10 ثوانٍ.
- لقطات شاشة دورية أثناء الجلسة النشطة.

الوكيل لا يعمل كمسجل مفاتيح، ولا يحفظ كلمات المرور أو النصوص التي يكتبها الموظف. كما يحجب عناوين النوافذ الحساسة ويتجنب تصوير تطبيقات كلمات المرور والتصفح الخاص عند اكتشافها.

### العمل دون إنترنت

- تُحفظ أحداث النشاط في SQLite محلية مشفرة.
- تُضغط لقطات الشاشة إلى JPEG بجودة 70 وبحد أقصى 1920×1080.
- تُشفّر اللقطات المنتظرة باستخدام AES-256-GCM.
- يُحفظ مفتاح التشفير داخل Windows Credential Manager من خلال مكتبة Keyring.
- عند عودة الاتصال يرسل الوكيل البيانات واللقطات تلقائيًا إلى الخادم.
- يستخدم التزامن معرفات ثابتة وعمليات upsert لمنع تكرار البيانات.

### تخزين لقطات الشاشة

- يحسب الخادم SHA-256 لمحتوى الصورة.
- الصور المتطابقة تستخدم ملفًا واحدًا بدل تخزين نسخ مكررة.
- سجل الالتقاط يبقى مرتبطًا بالموظف والجلسة ووقت الالتقاط.
- طبقة التخزين معرفة من خلال واجهة مستقلة، لذلك يمكن نقل الملفات من التخزين المحلي إلى تخزين سحابي لاحقًا دون تغيير بقية النظام.

## 3. كيف يعمل النظام؟

1. ينشئ المدير حساب الموظف ومهامه من الويب.
2. يسجل الموظف الدخول في وكيل Windows.
3. يبدأ الموظف جلسة العمل.
4. يبدأ الوكيل جمع عينات النشاط واللقطات محليًا.
5. يرسل الوكيل دفعات النشاط إلى REST API عند توفر الإنترنت.
6. يتحقق الخادم من هوية الموظف والمؤسسة والجلسة، ثم يخزن البيانات ويسجل عملية المزامنة في سجل التدقيق.
7. تجمع وحدة التحليلات العينات اليومية وتحسب الوقت النشط والخمول ودرجات التركيز والإنتاجية.
8. يستطيع المدير فتح ملف الموظف ومشاهدة بياناته ولقطاته وتحليله.
9. عند طلب تحليل ذكي، تعالج وحدة AI البيانات في الخلفية وتنتج التصنيفات والاتجاهات والتوصيات، ثم تنشئ إشعارًا عند الاكتمال.

## 4. حساب درجات الأداء

- تعتبر العينة خاملة عندما يصل `idleSeconds` إلى 60 ثانية أو أكثر.
- `Active time = Tracked time - Idle time`.
- درجة التركيز تعتمد على:
  - نسبة الوقت النشط: 70%.
  - استمرارية العمل وقلة تبديل النوافذ: 30%.
- درجة الإنتاجية تعتمد على:
  - نسبة الوقت النشط: 60%.
  - درجة التركيز: 40%.
- جميع الدرجات محصورة بين 0 و100.

هذه المعادلات قابلة للتفسير وثابتة، وليست نموذج ذكاء اصطناعي.

## 5. الذكاء الاصطناعي المستخدم

النظام لا يستخدم حاليًا OpenAI أو ChatGPT أو نموذجًا لغويًا سحابيًا، ولا يستخدم شبكة عصبية مدربة. المستخدم هو محرك محلي قابل للتفسير مكوّن من جزأين معزولين خلف واجهات برمجية، بحيث يمكن استبدالهما مستقبلًا بنموذج تعلم آلي دون التأثير على منطق النظام.

### Weighted Activity Classifier — الإصدار 1.0.0

مصنف موزون يعتمد على التطبيق النشط وعنوان النافذة وعنوان صفحة المتصفح ووقت الخمول. يصنف النشاط إلى:

- `WORK`: عمل.
- `COMMUNICATION`: تواصل.
- `BROWSING`: تصفح.
- `ENTERTAINMENT`: ترفيه.
- `IDLE`: خمول.
- `OTHER`: نشاط آخر.

يستخدم كلمات دلالية بأوزان مختلفة، ثم يحول النتائج إلى درجة ثقة احتمالية. يعتبر العمل والتواصل نشاطين منتجين. ويحفظ سبب التصنيف والكلمات المطابقة والدرجات لتكون النتيجة قابلة للمراجعة.

### Statistical Insight Generator

يحلل نتائج الأيام والتصنيفات ويولد:

- اتجاه الإنتاجية: يتحسن، مستقر، أو يتراجع.
- ميل تغير الإنتاجية باستخدام الانحدار الخطي البسيط.
- توزيع الوقت حسب تصنيف النشاط.
- توصية بتقليل الخمول عندما تتجاوز نسبته 25%.
- توصية بتقليل الترفيه عندما تتجاوز نسبته 15%.
- تنبيه عند وجود اتجاه إنتاجية متراجع.
- توصية بالمحافظة على النمط الحالي عندما تكون النتائج مستقرة ولا توجد مشكلة واضحة.

### أين يُستخدم الذكاء الاصطناعي؟

- داخل `apps/api/src/ai` فقط.
- تصنيف أحداث النشاط بعد وصولها من وكيل Windows.
- إنشاء التحليلات والتوصيات عند طلب المدير من صفحة الرؤى الذكية.
- حفظ النتائج في `activity_classifications` و`ai_analysis_jobs`.
- إرسال إشعار `AI_ANALYSIS_COMPLETED` بعد اكتمال المعالجة.
- تسجيل طلب التحليل ونتيجته في سجل التدقيق.

لا تُستخدم وحدة AI في المصادقة أو إدارة المستخدمين أو المهام أو رفع اللقطات، ولذلك يمكن ترقيتها أو استبدالها بصورة مستقلة.

## 6. الأدوات والتقنيات المستخدمة

### تطبيق المدير على الويب

- Next.js 16: تطبيق الويب والتوجيه وواجهات API الوسيطة.
- React 19: بناء الواجهات التفاعلية.
- TypeScript 5.9: الأنواع والتحقق أثناء التطوير.
- CSS مخصص: التصميم المتجاوب، RTL/LTR، والوضعان الفاتح والداكن.
- Server-side API proxy: حفظ رموز الدخول داخل Cookies من نوع HttpOnly وعدم كشفها لـ JavaScript في المتصفح.

### Backend API

- Node.js وNestJS 11: بناء REST API بوحدات مستقلة.
- Prisma 6: التعامل الآمن مع MySQL والترحيلات.
- MySQL/MariaDB: تخزين المستخدمين والمؤسسات والمهام والجلسات والأحداث والتحليلات وسجلات التدقيق.
- Passport وpassport-jwt و`@nestjs/jwt`: المصادقة باستخدام JWT.
- Argon2id: تشفير كلمات المرور.
- class-validator وclass-transformer: التحقق من مدخلات API ومنع الحقول غير المسموحة.
- Helmet: إضافة رؤوس حماية HTTP.
- `@nestjs/throttler`: تحديد معدل الطلبات.
- Multer: استقبال ملفات لقطات الشاشة.
- PDFKit: إنشاء تقارير PDF.
- xlsx-populate: إنشاء ملفات Excel.
- Jest وSupertest: اختبارات الوحدة وواجهات HTTP.

### وكيل Windows

- Tauri 2: تطبيق Windows خفيف باستخدام WebView بدل تضمين متصفح كامل.
- Rust: جامع النشاط والمزامنة والتشفير والتعامل مع Windows APIs.
- React وVite وTypeScript: واجهة الوكيل.
- windows crate: قراءة النافذة النشطة والخمول ونشاط الإدخال.
- sysinfo: قراءة قائمة التطبيقات والعمليات المفتوحة.
- screenshots: التقاط الشاشة.
- image: تصغير الصور وضغطها إلى JPEG.
- rusqlite: قائمة الانتظار المحلية دون إنترنت.
- AES-GCM: تشفير الملفات المحلية.
- keyring: حفظ مفتاح التشفير في Windows Credential Manager.
- reqwest مع rustls: الاتصال الآمن بـ REST API ورفع الملفات.
- Tokio: مهام المزامنة غير المتزامنة.
- MSI وNSIS: حزم تثبيت Windows.

### التشغيل والجودة

- npm workspaces: إدارة تطبيقات المشروع من مستودع واحد مع بقاء حدودها مستقلة.
- ESLint: جودة كود TypeScript.
- Jest وVitest: الاختبارات.
- PowerShell: التشغيل المحلي والنسخ الاحتياطي والاستعادة والبناء الإنتاجي.
- Prometheus metrics: مقاييس تشغيل API.
- Structured JSON logging: سجلات قابلة للبحث مع Request ID.

## 7. الحماية والخصوصية

- كلمات المرور مشفرة باستخدام Argon2id ولا يمكن استرجاعها كنص صريح.
- Access token قصير العمر مع Refresh token دوّار ومخزن في الخادم على شكل hash.
- فصل الصلاحيات إلى Admin وManager وEmployee.
- عزل البيانات حسب المؤسسة.
- التحقق من جميع المدخلات وحظر الحقول غير المعروفة.
- تخزين اللقطات خارج المجلد العام وعدم إتاحتها إلا بعد التحقق من الصلاحية.
- سجل تدقيق للمصادقة والمستخدمين والمهام والمزامنة والتحليلات والإجراءات الإدارية.
- إخفاء النوافذ الحساسة ومنع تصويرها عند اكتشافها.

## 9. حدود حالية مهمة

- يلتقط وكيل Windows الشاشة الأولى فقط حاليًا.
- يحصل الوكيل على عنوان صفحة المتصفح، وليس URL الكامل، لأن قراءة الرابط الكامل تحتاج إضافة متصفح أو تكاملًا إضافيًا.
- التصنيف الذكي الحالي عملي وقابل للتفسير، لكنه يعتمد قواعد وأوزانًا محددة مسبقًا وليس نموذجًا يتعلم تلقائيًا من بيانات المؤسسة.
- معالجة AI تعمل داخل عملية API بخلفية خفيفة؛ عند التوسع الكبير يمكن نقلها إلى عامل معالجة مستقل مع بقاء الواجهات الحالية.
